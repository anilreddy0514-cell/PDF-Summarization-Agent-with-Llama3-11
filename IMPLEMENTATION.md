# Implementation Document

## Objective

Provide a local web interface for uploading a text-based PDF and receiving a readable summary generated by Llama 3 through Ollama. FastAPI owns the upload and orchestration path; the browser never contacts Ollama directly.

## Components

- `app/main.py` serves the page and implements `POST /api/summarize`.
- `app/pdf_utils.py` validates the PDF signature, extracts page text with pypdf, enforces the page ceiling, and segments text with overlap.
- `app/ollama.py` sends non-streaming chat requests to Ollama and reduces chunk summaries hierarchically until one summary remains.
- `templates/index.html`, `static/style.css`, and `static/app.js` implement the upload, drag-and-drop, loading, result, copy, and error states.
- `tests/test_pdf_utils.py` covers chunk boundaries and basic PDF input validation.

## Request flow

1. The browser posts one file as multipart form data to `/api/summarize`.
2. FastAPI requires a `.pdf` filename and reads at most the configured byte limit plus one byte to detect oversized uploads.
3. The PDF helper checks the `%PDF-` signature, rejects encrypted or malformed files, enforces a 250-page ceiling, and extracts text from each page.
4. Empty extraction is rejected with guidance that scanned documents need OCR.
5. Extracted text is split into chunks of at most 12,000 characters with 500 characters of overlap. Sentence and paragraph boundaries are preferred when available.
6. Each chunk is summarized by the configured Ollama model. For multi-chunk documents, summaries are grouped and combined in rounds until a single response remains.
7. The API returns summary text and document metadata. The browser renders text safely and exposes a copy action.

## Configuration

Copy `.env.example` to `.env` before starting the app. `OLLAMA_BASE_URL` defaults to `http://localhost:11434`, `OLLAMA_MODEL` to `llama3.1:8b`, the request timeout to 180 seconds, and the upload limit to 20 MB. Pull the model once with `ollama pull llama3.1:8b`.

## Errors and operational notes

- Invalid extension or PDF signature: HTTP 400 or 422 with a user-readable detail.
- Oversized upload: HTTP 413.
- Encrypted, malformed, oversized-page-count, or textless PDF: HTTP 422.
- Ollama unavailable, timed out, missing the model, or returning an invalid response: HTTP 503 with a recovery hint.
- Text extraction is not OCR. Scanned documents need a future OCR stage (for example, Tesseract) before chunking.
- The app limits the incoming file and page count, but model work is sequential and latency scales with the number of chunks. Production deployment should add request concurrency limits, authentication if exposed beyond localhost, and structured operational logging.

## Verification

Run `pytest` for the focused PDF utility tests. Start Ollama and pull the configured model before manually exercising the upload flow end to end.
